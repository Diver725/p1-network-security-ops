# 安全事件报告 02：Web SQL 注入事件

- 报告编号：P1-IR-2026-0910-02
- 事件日期：2026-09-10
- 报告日期：2026-09-10
- 编制：实验演练（隔离内网）
- 事件等级：中（攻击被 WAF 拦截，未成功）

## 一、事件概述
2026-09-10 21:55，模拟攻击方（管理机 192.168.20.254）向受雷池 WAF（p1-waf，192.168.20.103）保护的 Web 站点发起 SQL 注入请求（URL 参数中携带 `or '1'='1` 逻辑注入载荷）。雷池 WAF 立即识别并拦截（HTTP 403），攻击事件记录为"已拦截 / SQL 注入"。随后按处置流程将攻击源加入 WAF IP 黑名单并验证封禁生效，确认后移除黑名单并恢复访问。

## 二、时间线
| 时间 | 事件 |
|---|---|
| 21:55:29 | 攻击方发起 SQL 注入请求：http://192.168.20.103/?id=1%27%20or%20%271%27=%271 |
| 21:55:29 | 雷池 WAF 拦截，返回 HTTP 403 + 拦截页 |
| 21:55:29 | WAF 攻击事件记录：类型 SQL 注入、来源 192.168.20.254、状态已拦截 |
| 处置阶段 | 将 192.168.20.254 加入 WAF IP 黑名单 |
| 验证阶段 | 正常访问也被拒绝：HTTP 403（黑名单生效） |
| 恢复阶段 | 移除黑名单条目后访问恢复：HTTP 200 |

## 三、攻击路径
```
攻击方（管理机 192.168.20.254）
   ↓ HTTP 请求（URL 参数携带 SQL 注入载荷）
雷池 WAF（p1-waf 192.168.20.103:80）
   ↓ 语义检测命中 SQL 注入规则 → 拦截（403）
（请求未到达）Web 服务器（p1-web 192.168.20.102:80）
```

## 四、IOC（失陷指标）
| 类型 | 内容 |
|---|---|
| 攻击源 IP | 192.168.20.254（演练用管理机） |
| 攻击目标 | Web 站点 http://192.168.20.103 |
| 攻击载荷 | `?id=1%27%20or%20%271%27=%271`（等价于 `' or '1'='1`） |
| 攻击类型 | SQL 注入（SQL Injection） |
| 检测设备 | 雷池 WAF（SafeLine） |
| 结果 | 已拦截（HTTP 403），未到达 Web 服务器 |

## 五、影响评估
- 攻击是否成功：**否**。请求在 WAF 层被拦截，未到达后端 Web 服务器。
- 业务可用性：正常访问不受影响（解除黑名单后 HTTP 200）。
- 风险等级：中（存在 Web 应用攻击尝试，防护有效）。

## 六、处置动作
1. 检测：WAF 实时拦截并记录攻击事件（类型/来源/URL/时间）
2. 研判：确认为 SQL 注入尝试，提取 IOC（攻击源 IP、载荷特征）
3. 处置：将攻击源 IP 加入 WAF 黑名单，验证封禁生效（正常访问同样被拒，HTTP 403）
4. 恢复：确认后移除黑名单条目，验证站点访问恢复正常（HTTP 200）
5. 留证：拦截页、攻击事件、黑名单验证、恢复验证截图归档

## 七、复盘与改进建议
1. **WAF 规则持续调优**：保持规则库更新，针对业务接口补充自定义规则
2. **应用侧加固**：SQL 注入根因在应用代码（未参数化查询），WAF 是补偿性控制，需推动开发修复（参数化查询/输入校验）
3. **告警联动**：将 WAF 攻击事件接入 Wazuh（集中审计），实现统一告警与关联分析
4. **访问控制**：对管理接口限制来源，降低暴露面
