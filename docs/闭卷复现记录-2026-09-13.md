## 一、任务卡 C：WAF 拦截 SQL 注入并处置

**做了什么**
1. 打开雷池控制台，找到防护应用配置，说出三项：监听端口 80、上游 http://192.168.20.102:80、运行模式=防护
2. 从 Windows 主机浏览器访问 http://192.168.20.103，确认正常访问（200）
3. 发起注入请求：`http://192.168.20.103/?id=1%27%20or%20%271%27%3D%271`
4. 观察到 403 + 雷池拦截页；WAF 攻击事件记录为「SQL 注入 / 已拦截」
5. 验证链：p1-web 的 nginx 访问日志中**没有**这条攻击请求（被 WAF 拦在门外）
6. 处置：把攻击源 192.168.20.254 加入 WAF 黑名单 → 验证 403 → 移除黑名单 → 验证恢复 200

**学到的概念**
- URL 结构：协议://主机:端口/路径?参数名=值&参数名2=值2
- 参数名由网站程序定义；参数是明文，可被观察和篡改
- 百分号编码：空格 %20、单引号 %27、等号 %3D（不用背，工具可自动生成）
- SQL 注入原理：程序把输入拼进带引号的 SQL；输入中的单引号先"逃出"字符串，再用 `or '1'='1'` 制造恒真条件，最后补齐引号保持语法合法
- WAF 看的是"请求内容"（特征），不是"来源网段"
- WAF 拦截的最硬证据：**后端日志里没有这条请求**
- 术语：误报（正常被拦）/ 漏报（攻击被放行）
- 坑：浏览器缓存会让"黑名单已生效"看起来像没生效 → 用 Ctrl+F5 / 无痕 / curl 看状态码

## 二、任务卡 A：fail2ban 封禁验证

**做了什么**
1. 在 p1-web（.102）用循环 + sshpass 对 p1-lan-client（.100）发起 6 次错误密码登录
2. 在 .100 上查看状态：Total failed 累计到 10、Currently banned 1、封禁 IP = 192.168.20.102
3. 解封 192.168.20.102，状态恢复（Currently banned 0）

**学到的概念**
- fail2ban 工作原理：**读日志**（不是判断规则）→ 按时间窗口统计失败 → 超阈值调用防火墙封源 IP
- jail：一套监控规则的名字（配置里方括号写的就是它，如 `[sshd]`）
  - `fail2ban-client status` = 列出所有 jail
  - `fail2ban-client status sshd` = 查看该 jail 详情
  - `fail2ban-client unban <IP>` = 解封
- server / client 模式：`fail2ban-server` 后台干活；`fail2ban-client` 是发指令的入口工具（类似 sshd/ssh、dockerd/docker、systemd/systemctl）
- 字段含义：Currently failed（当前窗口计数，封禁后清零）、Total failed（累计）、Currently banned（当前封禁数）、Total banned（历史累计）
- 为什么第一次 5 次失败没封：fail2ban 处理日志有秒级延迟，且计数在封禁后会重置
- ignoreself：忽略来自**本机自身**的失败（含 127.0.0.1 和本机网卡 IP），避免把自己锁死；所以测试必须从**另一台机器**发起
- 127.0.0.1 = 回环地址，指向自己；用途是本机程序间通信、只允许本机访问的服务、排除网络因素的测试

## 三、任务卡 D：SSH 加固复测

**做了什么**
1. 用 `sshd --help` 学会读 usage（方括号=可选，字母选项可合并写）
2. 用 `man sshd` 查选项含义（`/` 搜索、`n` 下一个、`q` 退出）
3. 用 `sudo sshd -T | grep -E "permitrootlogin|maxauthtries|allowusers|clientaliveinterval"` 查看实际生效配置
4. 确认四项加固：PermitRootLogin no、MaxAuthTries 3、AllowUsers lab、ClientAliveInterval 300（配合 ClientAliveCountMax 2）

**学到的概念**
- 改配置的标准流程（5 步）：**备份 → 追加加固配置 → 语法检查（sshd -t）→ 重启/重载服务 → 另开窗口验证**
- `sshd -t` = 只检查语法，不重启服务（防止配置写错导致 SSH 起不来、把自己锁在门外）
- `sshd -T` = 打印实际生效配置（两者容易混，注意大小写）
- sshd_config 语法：**参数名 + 空格 + 值**（不是等号）
- 加固项放在 drop-in 文件 `/etc/ssh/sshd_config.d/99-hardening.conf`，不改主配置，便于维护和撤销
- 四项加固的作用：禁 root（防最高权限账号被爆破）、限尝试次数（防暴力破解）、限用户（缩小攻击面）、空闲超时（防挂机会话被利用）
- ssh 与 sshd 的区别：ssh = 客户端（连别人）；sshd = 服务端守护进程（等别人连）；`d` = daemon
- Ubuntu 服务名是 `ssh`（`systemctl restart ssh`），但启动的程序是 sshd
- grep 的两种输入来源：搜文件（`grep 关键词 文件`）与搜上一条命令输出（`命令 | grep 关键词`）
- 引号规则：含空格或 `|` 等特殊字符时必须加引号（不加会被 shell 当管道解释）
