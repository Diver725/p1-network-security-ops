## 二、核心流程卡（合上答案，先自己讲一遍）

> 每张卡的"步骤要点"只列骨架，不含完整命令；目的不是背命令，而是能说清"先做什么、为什么、怎么验证"。

### F1 网络分区与 pfSense 部署
- **目标**：让"外网"和"内网"隔离，pfSense 作为唯一通道
- **步骤要点**：建 host-only 网段 → 建 NAT 网络（模拟外网）→ 新建 pfSense 虚拟机（双网卡）→ 安装系统 → 配 WAN/LAN 地址 → 开 DHCP
- **关键概念**：私网 vs 公网、子网/24、网关、DHCP、NAT
- **常见坑**：网卡连接方式选错（普通 NAT vs NAT 网络）；WAN 默认勾选 Block private networks 会拦掉私网模拟的外网流量
- **自测**：① 为什么 WAN 默认阻断入站、LAN 默认放行出站？② 一台设备怎么能同时属于两个网段？

### F2 内网链路验证
- **目标**：证明内网机器能经防火墙上网
- **步骤要点**：客户端接内网 → 自动获取 IP → 查 IP 与默认网关 → ping 网关 → ping 公网 → 更新软件源
- **关键概念**：DHCP 租约、默认路由、NAT 地址转换、DNS 解析链
- **常见坑**：两台机器同 IP（DHCP 复用）；DNS 全部 SERVFAIL（要分层排查）；内网机器直接配了公网 DNS 是临时方案
- **自测**：① DNS 不通和路由不通怎么区分？② 为什么要给服务器配固定 IP？怎么避免和 DHCP 池冲突？

### F3 SSH 加固与复测
- **目标**：把 SSH 管严，同时不把自己锁在外面
- **步骤要点**：备份配置 → 追加加固项（禁 root 登录、限制可登录用户、限制尝试次数、空闲超时）→ 语法检查 → 重启服务 → 另开窗口验证
- **关键概念**：sshd_config 与 drop-in 配置、语法检查、systemd 服务管理、密钥认证 vs 密码认证
- **常见坑**：改完不验证就断开旧连接；直接改主配置不备份
- **自测**：① 禁 root 登录防的是什么？② 空闲超时防的是什么场景？

### F4 fail2ban 封禁
- **目标**：暴力破解自动封禁来源 IP
- **步骤要点**：安装 → 写 jail 配置（封禁时长、统计窗口、失败阈值、日志来源）→ 启动并设自启 → **从另一台机器**制造失败 → 查看状态 → 解封
- **关键概念**：日志采集、阈值统计、调用防火墙封禁；bantime/findtime/maxretry；ignoreself
- **常见坑**：journal 单元名对不上（ssh.service vs sshd.service）；本机测试永远不触发（ignoreself）
- **自测**：① fail2ban 工作原理一句话？② 为什么要从别的机器测试？③ 怎么解封？

### F5 Wazuh 部署与 Agent 接入
- **目标**：多台机器的日志集中到一处、可搜索可告警
- **步骤要点**：准备 8G 机器与足够磁盘 → 安装（单节点）→ 登录控制台 → 从向导生成 Agent 安装命令 → 在目标机安装并启动 → Endpoints 看 Active → Discover 搜 agent.name 验证日志
- **关键概念**：Agent/Manager/Indexer/Dashboard 四个角色；集中审计；告警级别（3-5 低、6-8 中、9-12 高、13-15 严重）
- **常见坑**：磁盘不足导致安装失败甚至包管理器损坏；Agent 列表 IP 显示 any（不影响上报）
- **自测**：① Wazuh 和 auditd 的区别？② 为什么等保要求"集中审计"？

### F6 告警研判与事件处置（SSH 爆破）
- **目标**：从告警走到处置闭环
- **步骤要点**：产生攻击 → 收到告警 → 研判（来源 IP、目标、次数、时间窗）→ 核实是否得手（成功登录记录、登录历史、审计记录）→ 处置（封禁）→ 恢复 → 写报告
- **关键概念**：IOC、MITRE ATT&CK、事件等级、时间线、复盘改进
- **常见坑**：只看告警不看"是否成功"；处置不留证据
- **自测**：① 收到爆破告警第一步做什么？② 怎么判断攻击有没有成功？

### F7 WAF 防护与 SQL 注入拦截
- **目标**：Web 攻击在 WAF 层被拦
- **步骤要点**：部署 Web 服务 → 部署 WAF → 添加防护应用（访问地址、监听端口、上游真实地址、拦截模式）→ 正常访问验证 → 发起注入攻击 → 看到拦截与攻击事件 → 拉黑攻击源 → 验证 → 恢复
- **关键概念**：WAF 与防火墙区别（看内容 vs 看地址端口）；SQL 注入原理；观察模式 vs 拦截模式
- **常见坑**：上游地址格式（要带 http://）；默认可能是观察模式（只记录不拦截）
- **自测**：① 怎么证明 WAF 生效？② WAF 能替代代码层的安全开发吗？

### F8 等保差距分析与整改闭环（R1-R4）
- **目标**：对照标准自查 → 整改 → 复测 → 报告
- **步骤要点**：按五层对照（通信网络/区域边界/计算环境/管理中心/物理环境）→ 列差距与优先级 → 逐项整改 → 复测留证 → 出整改报告
- **本轮整改**：R1 集中审计覆盖扩大（Web 接入 Wazuh）；R2 身份鉴别增强（会话超时 + fail2ban）；R3 时间同步；R4 边界日志集中（pfSense 日志入 Wazuh）
- **关键概念**：等保五层、集中管控、集中审计、时间同步、整改闭环
- **常见坑**：日志类服务磁盘要留足；syslog 接收要独立 remote 块；Filebeat archives 缩进要对
- **自测**：① 差距分析的作用是什么？② R1 对应等保哪条要求？

### F9 防火墙日志接入 Wazuh（R4）
- **目标**：边界日志也进集中审计
- **步骤要点**：Wazuh 侧开远程 syslog 接收（独立 remote 块）→ 开启全量日志记录 → Filebeat 启用 archives → pfSense 侧配置远程日志并勾选防火墙/系统事件 → LAN 规则开日志 → 制造流量 → 在 archives 索引中验证
- **关键概念**：syslog（UDP 514）、archives 索引、数据视图
- **常见坑**：一个 remote 块只能有一种 connection；Filebeat 的 enabled 要缩进到 archives 之下
- **自测**：为什么要收边界日志？它和主机日志如何互补？

## 四、P1 高频坑清单（一句话 + 对策）

1. 安装器下载失败 → 虚拟机不走系统代理，开代理的"虚拟网卡(TUN)"模式
2. 内网 DNS 全 SERVFAIL → 分层排查：本机→网关 DNS→上游 DNS，逐层用 nslookup 指定服务器验证
3. 两台机器同 IP → DHCP 复用离线机器的地址；服务器用固定 IP，DHCP 池与静态段错开
4. 磁盘写满导致安装失败 → 日志/索引类服务预留大磁盘（Wazuh 建议 50G+）
5. 包管理器损坏（dpkg 半装半卸）→ 修复流程：dpkg --configure -a → apt --fix-broken → 强制清除残留
6. 克隆机 SSH 主机密钥相同 → 重新生成主机密钥（rm + ssh-keygen -A + 重启 ssh）
7. fail2ban 不生效 → ignoreself 会忽略本机来源，必须从其他主机测试
8. pfSense 拦掉私网模拟流量 → WAN 的 Block private networks 需在实验环境关闭
9. Wazuh 收不到 syslog → 每个 remote 块只能一种 connection，syslog 必须独立成块
10. 控制台看不到 archives → Filebeat 的 archives.enabled 缩进错误；需正确缩进后重启
11. Suricata 只有 415 条内置规则 → pfSense 2.9 + Suricata 8 插件兼容缺陷，改用替代方案
12. 规则改了却看起来没生效 → 可能是浏览器缓存：用 Ctrl+F5 / 无痕 / curl 看状态码再判断

20. Suricata 规则加载失败时，你的排查思路是什么？

### 答案要点（先自己答完再看）
1. WAN 是不可信区域，默认拒绝入站；LAN 是可信内网，允许出站并做 NAT。
2. 防火墙天生"脚踏两条船"：一张网卡接外网段，一张接内网段，在两者之间转发并做策略控制。
3. 机器关机超过租约期，地址被 DHCP 视为空闲并分配给新机器；对策：服务器静态 IP + DHCP 池与静态段错开 + 可选 DHCP 保留。
4. 直接用 nslookup 指定不同 DNS 服务器测试：能解析=网络通、解析失败=DNS 问题；ping 也通但域名不行 → DNS 问题。
5. 禁 root 登录防 root 被爆破；限制用户缩小攻击面；限制尝试次数防爆破；空闲超时防挂机被劫持。
6. 防止配置写错把自己锁在外面——新连接验证成功后再断开旧连接。
7. 读日志 → 按时间窗口统计失败次数 → 超阈值调用防火墙封禁 IP；ignoreself 让它忽略本机来源。
8. auditd 是单机审计记录；Wazuh 是多机集中采集 + 规则分析 + 告警 + 可视化。
9. 研判（来源/次数/时间窗/是否得手）→ 处置（封禁）→ 痕迹检查 → 恢复 → 报告。
10. 看成功登录记录（Accepted）、登录历史（last）、审计记录（auditd），确认有无成功会话或文件篡改。
11. WAF 看 HTTP 内容，防火墙看 IP/端口；SQL 注入根本手段是参数化查询/输入校验，WAF 是补偿控制。
12. 正常请求放行（200）、攻击请求被拦（403）并有攻击事件记录。
13. 安全通信网络、安全区域边界、安全计算环境、安全管理中心、安全物理环境。
14. 差距分析是"对照标准找出没做到的地方"；整改闭环：发现问题→整改→复测→留证→报告。
15. R1 集中审计（管理中心/集中审计）；R2 身份鉴别与入侵防范；R3 时间同步；R4 边界安全审计。
16. 边界日志能反映"谁在攻击边界"，与主机日志互补，便于关联分析和溯源。
17. 索引/日志会持续增长，磁盘不足会导致服务异常甚至数据损坏。
18. 克隆机共用模板密钥会导致身份不可区分（有冒充风险），每台机器应有唯一主机密钥。
19. 一是接收端 remote 块配置错误（连接类型未独立成块）；二是发送端未真正发出/被防火墙拦；三是 Filebeat 索引未开启。
20. 看引擎日志规则数 → 找规则文件是否下载并注册 → 检查类别列表 → 检查插件是否把规则编入接口规则文件 → 必要时重装插件或改用独立部署。
