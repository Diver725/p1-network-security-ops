## 三、三个项目的 30 秒介绍

### P1

> 我搭建了一个企业网络安全实验环境，使用 pfSense 完成网络分区，部署 Suricata、雷池 WAF 和 Wazuh，完成等保差距分析、整改复测，并做了 SSH 暴破和 Web SQL 注入两起安全事件演练。

### P2

> 我使用 Lynis 和 GVM 对多台 Ubuntu 服务器完成基线和漏洞扫描，再通过 Ansible 批量实施 SSH、UFW、sysctl、PAM 和 auditd 等加固，最后复测，Lynis 加固指数从 57 提升到 75，GVM Low 风险从 9 降到 0。

### P3

> 我搭建了基于 Wazuh 的 SOC 实验环境，完成 SSH 暴破、SQL 注入、目录扫描和可疑 Web 文件四类场景，编写三条自定义规则，并完成告警研判、IOC 提取、UFW 阻断、文件隔离和事件报告闭环。

## 四、项目 2 分钟讲解结构

每个项目都按同一结构讲：

```text
背景与目标

→ 一个真实排错或决策案例
```

### P1 可讲案例

- pfSense 下载失败与代理虚拟网卡模式
- 内网 DNS SERVFAIL 分层排查
- fail2ban 因 ignoreself 不生效
- SQL 注入被 WAF 拦截后如何验证

### P2 可讲案例

- GVM 扫描认证和无认证的区别
- UFW 开启前先放行 SSH
- Ansible 幂等性验证
- CPU 微码类漏洞为什么不能靠客户机包更新解决

### P3 可讲案例

- Rule 100200 为什么用 `if_matched_sid`、`frequency` 和 `same_source_ip`
- FIM 为什么能发现文件变化但不能直接告诉是谁写的
- 为什么要先隔离 Webshell 文件而不是直接删除
- UFW 临时阻断后为什么必须验证并回滚

## 五、简历项目描述草稿

### P1：企业网络安全建设与等保整改

1. 基于 pfSense 完成内外网和 DMZ 网络分区，部署 Suricata IDS、雷池 WAF 与 Wazuh SIEM，覆盖 5 台虚拟机和 3 个网段。
2. 完成业务主机安全加固，包括 SSH、口令复杂度、无用服务清理、SUID 盘点和 auditd 审计，并通过 fail2ban 实现 SSH 暴破自动封禁。
3. 按等保 2.0 三级要求完成差距分析、整改和复测，输出整改报告。
4. 完成 SSH 暴破和 SQL 注入安全事件演练，输出含时间线、IOC、处置和验证结果的事件报告。

### P2：企业漏洞管理与安全基线自动化加固

1. 使用 nmap 和 Ansible 建立 4 台 Ubuntu 主机的资产清单和统一管理链路。
2. 使用 Lynis 和 GVM 完成基线核查与认证漏洞扫描，建立加固前风险基线。
3. 编写 Ansible 加固剧本，实施 SSH、UFW、sysctl、PAM、fail2ban 和 auditd 等配置。
4. 完成加固前后复测：Lynis hardening index 从 57 提升到 75，warnings 从 2 降到 0，GVM Low 风险从 9 降到 0，并记录 CPU 微码类残余风险。

### P3：SOC 安全运营与护网应急响应

1. 基于 Wazuh 4.14 搭建单节点 SOC 实验环境，接入 Ubuntu Web 靶机 Agent，采集 SSH、Apache、系统日志和 FIM 事件。
2. 编写三条自定义规则，分别覆盖 SQL 注入内容特征、目录扫描频率关联和 Web 上传目录文件新增。
3. 完成 SSH 暴破、SQL 注入、目录扫描和可疑 Web 文件四类场景的检测、研判和应急处置。
4. 输出四份安全事件报告，包含原始日志、Wazuh 告警、IOC、影响评估、处置动作、验证结果和改进建议。
