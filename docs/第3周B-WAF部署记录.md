# P1 第 3 周 B 记录：雷池 WAF + Web 服务器

日期：2026-09-08

## 目标
部署 Web 服务器（业务系统）并在其前面加 Web 应用防火墙（雷池 SafeLine），验证 WAF 能拦截 Web 攻击（SQL 注入）。

## 环境与新增虚拟机
| 虚拟机 | 固定 IP | 作用 |
|---|---|---|
| p1-web | 192.168.20.102 | Web 服务器（nginx，测试站点） |
| p1-waf | 192.168.20.103 | 雷池 WAF（SafeLine 9.4.1，Docker 部署） |

补充：克隆机均重新生成 SSH 主机密钥（模板克隆默认密钥相同，需唯一化）。

## 部署过程
1. p1-web：装 nginx，写测试页，监听 80 端口（注意：中文经终端传输会乱码，测试页改用英文）
2. p1-waf：安装雷池 SafeLine（官方 setup.sh，安装脚本名为 setup.sh 而非 install.sh），默认目录 /data/safeline
3. 雷池控制台（https://192.168.20.103:9443）添加防护应用：
   - 域名：192.168.20.103，端口 80
   - 上游服务器：http://192.168.20.102:80（注意要带协议前缀 http://）
   - 运行模式：拦截（防护）模式

## 验证结果（截图见 screenshots/）
1. 正常访问 http://192.168.20.103 → 返回 200，显示测试页（流量透明穿过 WAF）
2. SQL 注入攻击：curl "http://192.168.20.103/?id=1%27%20or%20%271%27=%271"
   → 返回 HTTP 403，页面为雷池拦截页（"访问已被拦截 / 请求存在恶意行为"）
3. 雷池攻击事件日志：记录"已拦截 + SQL 注入"，来源 192.168.20.254（模拟攻击者）

## 学习点
- WAF = Web Application Firewall：检查 HTTP 请求内容（SQL 注入/XSS 等），与网络防火墙（按 IP/端口）互补
- SQL 注入原理：输入中夹带 SQL 代码，程序未过滤拼入查询即被利用（如 ' or '1'='1）
- 雷池新站点默认可能为"观察"模式（只记录不拦截），要切成"拦截"模式才生效
- 上游服务器填完整 URL（协议+IP+端口）
- 正常流量经 WAF 与直接访问看起来一样，判断 WAF 生效要看攻击流量是否被拦
