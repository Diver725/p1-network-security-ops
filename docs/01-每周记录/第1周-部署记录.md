# P1 第 1 周部署记录：网络分区 + pfSense + Suricata

日期：2026-09-05　环境：VirtualBox 7.2.16 / Windows 主机（24GB 内存）

## 1. 本周目标
搭建"外网 → 防火墙 → 内网"的分区网络；部署 pfSense 防火墙；启用 Suricata IPS；验证内网机器能经防火墙上网。

## 2. 网络规划

| 网段 | 用途 | 网关 / 说明 |
|---|---|---|
| 10.0.2.0/24（NAT 网络 p1-wan） | 模拟外网 | 出口 10.0.2.1（VirtualBox 提供，可真实上网） |
| 192.168.20.0/24（host-only #3） | 内网 | 网关 192.168.20.1 = pfSense LAN 口 |
| 192.168.10.0/24（host-only #2） | DMZ（备用） | 后续放 Web 服务器 |
| 192.168.56.0/24（host-only） | 课程虚拟机 SEED | 与实验无关，未改动 |

## 3. 关键配置

- pfSense CE 2.8.1（Netgate Installer 安装）
  - WAN = em0：静态 10.0.2.10/24，网关 10.0.2.1，DNS 223.5.5.5
  - LAN = em1：192.168.20.1/24，开启 DHCP（192.168.20.100 ~ 199）
  - DHCP 下发的 DNS：223.5.5.5 / 223.6.6.6（原因见"已知问题"）
- Ubuntu Server 24.04.4 基础模板 `ubuntu2404-template`（快照 base-clean）
  - 从模板完整克隆出内网客户端 `p1-lan-client`（DHCP 拿到 192.168.20.100）
- Suricata：安装在 pfSense，WAN 口启用，使用 ETOpen 免费规则集

## 4. 验证结果（截图见 screenshots/）

- pfSense 本机：ping 10.0.2.1 ✅ / ping 223.5.5.5 ✅（能上网）
- p1-lan-client：DHCP 获 192.168.20.100，默认网关 192.168.20.1 ✅
- 客户端 ping 网关 ✅ / ping 公网 223.5.5.5 ✅（流量穿过防火墙 NAT）
- 客户端 apt update 正常 ✅（能联网装软件）

## 5. 遇到的问题与处理（重要经验）

1. **pfSense 联网安装器下载卡死**：主机开了代理，虚拟机 NAT 不走代理 → 把代理切到"虚拟网卡(TUN)"模式后下载成功。
2. **客户端 DNS 全部 SERVFAIL**：直连 223.5.5.5 正常、pfSense 本地解析正常，但 pfSense 内置 DNS 服务（Resolver/Forwarder）对 LAN 客户端返回 SERVFAIL；切换 Resolver/Forwarder、重启均未解决。
   - 临时方案：DHCP 直接下发公网 DNS 223.5.5.5 / 223.6.6.6，客户端绕过 pfSense 内置 DNS。
   - 待办：第 3 周部署 Wazuh 前，研究 pfSense 内置 DNS 对 LAN 失效的原因（学习点：Resolver vs Forwarder）。
