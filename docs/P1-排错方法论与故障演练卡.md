# P1 排错方法论与故障演练卡

> 目的：解决"遇到错误不知道从哪查"的问题。方法比命令重要——命令可以查，思路必须练。

## 一、核心心法：排错不是猜，是"分层 + 二分"

### 四步法
1. **期望**：正常情况下，这里应该是什么样？（服务在跑？端口在听？能返回 200？）
2. **现象**：实际看到什么？（报错原文、状态、时间点——先记录，别急着改）
3. **分层**：问题最可能在哪一层？（见下方分层图）
4. **最小验证**：用一条命令验证一层；**每次只改一个变量**，改完立即验证

### 分层图（从下往上查）
```
应用层：服务本身是否正常（nginx / wazuh-agent / fail2ban / suricata）
系统层：进程在不在、端口是否监听、资源是否足够（磁盘/内存）、权限对不对
网络层：IP 地址、路由、DNS、端口连通、防火墙策略
对端层：上游服务、日志接收端、时间源、证书
```

## 二、七个查错入口（遇到问题先把这七个过一遍）

| 入口 | 常用命令族 | 看什么 |
|---|---|---|
| 服务状态 | systemctl status 服务名 | running / failed、最近日志 |
| 日志 | journalctl -u 服务名、tail -n 50、grep | 报错原文、时间点 |
| 端口/进程 | ss -tlnp、ps aux | 有没有监听、进程在不在 |
| 配置语法 | 服务自带测试命令（如 sshd -t、nginx -t） | 配置是否合法 |
| 资源 | df -h、free -h | 磁盘满 / 内存不足 |
| 网络连通 | ip a、ip route、ping、nslookup、nc -vz | 地址、网关、解析、端口通不通 |
| 权限/时间 | ls -l、id、timedatectl | 属主权限、时间是否同步 |

## 三、三个真实案例（按四步法复盘）

### 案例 1：内网 DNS 全部 SERVFAIL
- **期望**：域名能正常解析
- **现象**：ping IP 通，但域名解析失败（SERVFAIL）
- **分层**：网络层 → DNS
- **验证顺序**：直接问公网 DNS（能解析）→ 直接问网关 DNS（失败）→ 定位到网关 DNS 服务
- **根因**：pfSense 内置 DNS 服务对 LAN 客户端异常；临时方案为 DHCP 直接下发公网 DNS
- **教训**：DNS 问题必须"逐层指定服务器"验证，不能只看"通不通"

### 案例 2：fail2ban 不封禁
- **期望**：多次失败后自动封禁来源 IP
- **现象**：状态里 Total failed 始终为 0
- **分层**：应用层（fail2ban 读取数据源）
- **验证顺序**：看 status 的数据源（journal 还是文件）→ 用 fail2ban-regex 测试过滤器能否匹配日志 → 看 fail2ban 自身日志
- **根因**：① journal 单元名不匹配（系统用 ssh.service，配置里找 sshd.service）；② ignoreself 规则忽略本机来源
- **教训**：先确认"数据源对不对"，再怀疑规则和阈值

### 案例 3：Wazuh 收不到 pfSense 日志
- **期望**：防火墙日志进入 Wazuh
- **现象**：514 端口无监听；控制台无 archives 索引
- **分层**：应用层（接收端配置）+ 数据管道（Filebeat 索引）
- **验证顺序**：引擎日志（csyslogd/remoted 报错）→ 端口监听（ss -lunp）→ archives 数据文件是否有来源 IP → Filebeat 配置与语法
- **根因**：① 一个 remote 块不能混放两种 connection，syslog 必须独立成块；② Filebeat 的 archives.enabled 缩进错误导致未启用
- **教训**：数据管道问题要"从接收端往上游查"，并且**先验证数据到了没有，再查展示层**

## 四、故障演练卡（现象 → 你要做的 → 分级提示）

> 用法：让 Codex 先制造故障（或用现有故障），你按四步法排查；卡住时按"一级→二级→三级"要提示。
> 一级：只给方向问题　二级：给命令族　三级：才给具体命令

### 演练 1：网站访问报 502
- 现象：浏览器访问站点返回 502 Bad Gateway
- 你要做的：说出期望、判断在哪一层、给出验证顺序
- 提示1：先确认 WAF 到上游这条路是否通
- 提示2：用"网络连通"和"服务状态"两类命令
- 提示3：从 WAF 机器测试上游 Web 的端口与页面
- 根因参考：上游 Web 服务未启动 / 端口不对 / 上游地址写错

### 演练 2：正常请求被 WAF 误拦
- 现象：正常访问也返回 403
- 你要做的：判断是规则问题、模式问题还是黑名单问题
- 提示1：先看是谁在拦——WAF 规则还是黑名单
- 提示2：查 WAF 的拦截日志与黑名单列表
- 提示3：检查是否误加黑名单，或规则过严
- 根因参考：演练时误把管理机 IP 加入黑名单；或规则误命中

### 演练 3：客户端 ping 不通网关
- 现象：内网机器无法 ping 通 192.168.20.1
- 你要做的：分层判断是链路、地址、防火墙还是虚拟机网络设置
- 提示1：本机地址和网卡状态是否正常
- 提示2：看 IP/路由 + 虚拟机网卡连接方式
- 提示3：确认 IP 是否冲突、网卡是否接在正确网段
- 根因参考：IP 冲突（两台同一地址）、网卡接错网络

### 演练 4：能 ping 通 IP，但域名解析失败
- 现象：ping 223.5.5.5 通，ping 域名失败
- 你要做的：区分 DNS 问题与网络问题
- 提示1：直接指定公共 DNS 测试解析
- 提示2：再看客户端当前使用的 DNS 是谁
- 提示3：检查 DHCP 下发的 DNS 与接收端 DNS 服务
- 根因参考：下发的 DNS 不可用 / DNS 服务异常

### 演练 5：Wazuh 看不到某台机器的日志
- 现象：Endpoints 里该机器状态异常或没有日志
- 你要做的：判断是 Agent、网络、Manager 还是索引/展示问题
- 提示1：先看 Agent 服务状态
- 提示2：确认 Agent 配置里的 Manager 地址、端口通不通
- 提示3：看 Endpoints 状态与 Discover 索引/时间范围
- 根因参考：Agent 未启动 / Manager 地址错误 / 端口被挡 / 时间范围选错

### 演练 6：fail2ban 不封禁
- 现象：多次错误登录但无封禁
- 你要做的：确认数据源 → 过滤规则 → 忽略规则
- 提示1：先确认 fail2ban 读的是哪份日志
- 提示2：用 fail2ban 自带工具测试过滤器
- 提示3：检查 ignoreself 与日志单元名
- 根因参考：本机来源被忽略 / 日志源不匹配

### 演练 7：pfSense 端口映射不生效
- 现象：外网访问映射端口失败
- 你要做的：确认映射规则、放行规则、目标服务、来源地址限制
- 提示1：先确认 NAT 规则与防火墙规则是否都存在
- 提示2：分别从防火墙、内网、外网测试目标端口
- 提示3：检查 WAN 是否拦截了私网/保留地址来源
- 根因参考：缺放行规则 / Block private networks 拦截私网模拟外网

### 演练 8：SSH 突然连不上
- 现象：无法 SSH 登录某台机器
- 你要做的：区分服务未启动、端口被挡、认证失败、IP 变化
- 提示1：先确认目标机器地址是否变了
- 提示2：看服务状态与端口监听；从本机控制台看日志
- 提示3：检查防火墙规则与 SSH 配置语法
- 根因参考：改配置后未验证、服务未启动、IP 变更、封禁规则生效

### 演练 9：服务异常，磁盘满导致
- 现象：某服务无法写入、报错或异常退出
- 你要做的：先查资源再查服务
- 提示1：查看磁盘剩余空间
- 提示2：找出哪些目录占用大（日志/索引/缓存）
- 提示3：清理或扩容，并检查服务是否恢复
- 根因参考：日志/索引暴涨占满磁盘（Wazuh 类服务常见）

### 演练 10：日志时间对不上 / 证书报错
- 现象：日志时间错乱、HTTPS 证书告警
- 你要做的：确认时间同步状态
- 提示1：看系统时间与同步状态
- 提示2：检查 NTP 服务与时间源可达性
- 提示3：确认时间源配置与防火墙放行
- 根因参考：时间未同步、时间源不可达

## 五、三级提示使用规则（我们练习时用）
- **一级（默认）**：只给方向性问题："你觉得问题在哪一层？""先确认哪件事？"
- **二级**：给命令族提示："用查服务状态的那类命令"
- **三级**：给具体命令（尽量不用）
每次求助后，记录：**卡在哪一层、为什么想不到**

## 六、明天怎么做（把任务卡 C 拆成三小步）

- **C1**：打开 WAF 控制台 → 找到防护应用配置 → 说出"监听端口 / 上游地址 / 运行模式"三项
- **C2**：自己构造并发出一次 SQL 注入请求 → 观察状态码与返回页面
- **C3**：把攻击源加入黑名单 → 验证 → 解封 → 验证；并解释"为什么拉黑后正常访问也被拒"

**每完成一小步就算成功**，不追求一口气做完。
